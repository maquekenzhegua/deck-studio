# 设计语言：从 1144 页真实 deck 里量出来的规则

这份文档不是审美宣言，是一次测量的记录。我们抓了 19 份 Fortune 100 公司的真实
投资者/年报 deck（Goldman Sachs、Walmart、Chevron、JPMorgan、Coca-Cola、UPS、
Intel、GM、CVS、Home Depot、Caterpillar、PepsiCo、ExxonMobil、Microsoft、
Nike、FedEx、Delta、IBM、Tesla），共 1144 页缩略图，量了三件事：**页面是深是浅、
墨迹占多少、字有多大**。然后才动手改渲染器。

复现：

```bash
python corpus/wiki_pull.py          # 下载 19 份 deck 的逐页缩略图
python corpus/refs_sheet.py         # 拼 contact sheet + 统计
open corpus/refs/sheet-covers.png   # 封面、章节页
open corpus/refs/sheet-sample.png   # 随机内容页
```

---

## 1. 量出来的五个事实

| 指标 | 实测 | 含义 |
| --- | --- | --- |
| 深浅分布 | 深色页 207 / 浅色页 937 | 深色是**节奏**，不是默认底色 |
| 单份 deck 的深色占比 | Goldman 93.5%、CVS 68.4%、GM 67.9% / JPMorgan 0.9%、Home Depot 2.9% | 每份 deck 选一种模式走到底，不随机深浅 |
| 内容页墨迹中位数 | 28.6% | 我们的旧稿是 18–28%，系统性偏空 |
| 高墨迹 deck | Walmart 86.8%、Caterpillar 49.4%、Home Depot 43.8% | 零售/工业用图片和信息图把版面填满 |
| 低墨迹 deck | Goldman 4.8%、Microsoft 13.4%、GM 14.3% | 金融/科技用大留白 + 一句结论，靠尺度而不是靠元素 |

结论：**"好看"不是装饰多，是每页有一个明确的视觉主角，并且整份 deck 的深浅、
字号、留白是同一套决定。** 旧渲染器每页都在 22% 墨迹、26pt 标题、同一张浅色底，
所以看起来像表格导出，而不是一份被设计过的文件。

## 2. 六个可执行规律

1. **封面和章节页是"场"，不是"页"。** 整版品牌色或全出血照片，字数 ≤ 12，
   字号 40–60pt。Chevron 用深蓝 + 一句结论；Walmart 用蓝底白字 + 人像 + 引语；
   Goldman 用黑底白衬线巨字。共同点：没有页眉、没有项目符号、没有第二个焦点。
2. **深浅交替制造章节感。** 封面/章节/结尾深色，内容页浅色；深色页负责停顿，
   浅色页负责论证。midnight 这类全暗主题只在演示厅有效，打印会糊。
3. **内容页靠网格和证据填满。** 真实内容页墨迹 35–70%：图表 + 右侧读法栏 +
   底部结论带 + 来源行。留白留在**页边**，不是留在版面中间。
4. **摄影是材料，不是配图。** 全出血照片 + 品牌色双色调（duotone），让一张
   工厂照/门店照和整套配色发生关系；缩在框里的照片等于没放。
5. **字体按行业分。** 金融用衬线（JPMorgan 米色纸 + Georgia 风），工业/科技用
   无衬线。中文标题用思源宋体、正文用微软雅黑，是最接近这个分工的本地组合。
6. **图表直接标注。** 没有图例、没有网格线、没有 y 轴刻度洪水；最大值一个强调色，
   其余退到灰；数值写在条形末端；右侧用三句话说明"这张图在说什么"。

## 3. 七个页面原型

| 原型 | 结构 | 规则 |
| --- | --- | --- |
| `title` | 深色场 + 46pt 论点句 + 副标 + 底部三列 KPI | 标题必须是结论，不是"2026 年度汇报" |
| `section` | 深色场 + 300pt 幽灵编号 + 44pt 章节问句 + 目录 | 章节页回答"接下来看什么" |
| `kpi_row` | 1–4 张大数字 + 单位内联 + 读法带 + 来源行 | 数字 78pt；单位跟着标签走，不漂在列尾 |
| `chart` | 左 8in 图 + 右 3.4in 读法栏（01/02/03） | 每张图必须有三句可读的结论 |
| `table` | 手绘行 + 分布条 + 转化率列 + 读法带 | 表头是量纲，不是字段名 |
| `image_full` / `split_image` | 全出血照片或"装裱"文档图 + 溯源块 | 文档图不当照片处理；标注文件、尺寸、是否二次加工 |
| `closing` | 深色场 + 左说明 + 右三条竖排动作 | 动作带证据（+34.0%、38.7%），不是口号 |

## 5. 我们踩过的反模式

- **幽灵元素**：封面上一个 150pt 的半透明年份压在 KPI 上 → 删掉，不靠"氛围字"撑场。
- **单位漂移**：`个 / 元 / 个` 三个小字漂在列右缘 → 改成 `订单数 · 个` 内联。
- **错误基线**：所有条形都从 42% 处起画，正数也被截断 → 只有存在负值时才用中线基线。
- **同色正负**：editorial 的最大正值和负值都是铁锈红 → 负值改用青绿 `#1F4E5F`。
- **压平趋势**：y 轴从 0 起，165→269 万看起来是直线 → 非零基线 + 端点标注 + 来源行注明。
- **把图表当照片**：白色底的 PNG 被 duotone 成紫色 → 先判 near-white 再决定装裱方式。
- **一页三个焦点**：标题、KPI、结论带同时在抢注意力 → 每页只允许一个视觉主角。

## 6. 验收

```bash
python -m deck.cli build samples/data --offline --theme editorial --out out/deck.pptx
python tools/qa.py out/deck.pptx --png out/deck
```

`qa.py` 会报：页数、墨迹中位数、字号越界、文本溢出、连续同版式、空白页，并给一个
0–100 的质量分。低于 90 分的页面不进"可交付"状态。


## 渲染器实测修正（2026-11-19，LibreOffice 渲染后逐页复查）

真实渲染器比 PPTX 结构更挑剔。下面这些是「看起来写对了、渲出来是错的」的实例，
都已经固化成代码约束：

| 现象 | 根因 | 约束 |
| --- | --- | --- |
| 表格每根条都带柔和阴影 | `add_shape` 的 `<p:style>` 里 `effectRef` 指定了阴影；`shadow.inherit=False` 只写空的 `effectLst`，PowerPoint 认，LibreOffice 不认 | 删掉整个 `<p:style>`，见 `visual._no_shadow` |
| 英雄数字 `977.2 万` 断成两行，落单的「万」压住标签 | CJK 与拉丁之间允许自动换行；字号按行高算能放下，按字宽算放不下 | `_fit` 之后再用 `text_width_pt` 收一次，并 `word_wrap=False` |
| 表格「分布」表头与条形起点差 46px | 表头 x 用列宽累加，条形 x 用另一套常量 | 一处算 `bar_x`，表头/条形/数值都引用它 |
| 转化率列漂在页面中间 | 数值列预留了 1.71in，转化列被推得太左 | 数值 1.30、转化 0.95、间隙 0.26，条形右端吃到转化列前 0.45in |
| 章节页标题两行贴在一起、说明贴脸 | 44pt 用 1.05 行距；说明用固定 y | 行距 1.14；说明按 `lines × size × 行距` 计算 y |
| 结尾页大标题压到右栏 | 42pt 一行宽 10.8in，右栏从 6.15in 开始 | 标题宽 4.55in 强制两行，右栏 34pt 竖排三条 |
| 照片页标题悬在页面中间 | 三个元素各自固定 y | 自下而上锚定：说明 → 标题 → kicker |
| 章节页目录只列 4 页、页码落到页脚 | 固定截断 | 列到下一个 section 为止（最多 5 条），行距 0.36 |

另加一条内容规则：**引用页只引用原文**。`compose._pull_quote` 从用户文档里挑一句
不含数字的话（含数字就必须可核对，改写过的引用不再是引用），署名到文件名。

### 封面与原始材料页（2026-11-19 晚）

- **封面遮罩要一次画完**：实心块 + 两段渐变拼出来的遮罩，在 LibreOffice 里会留下一条竖直接缝——
  渲染器对相邻 alpha 渐变做色带量化。改成单形状多停靠点（`add_scrim`，0/34 为 100%，72/100 为 26/30%）
  后接缝消失。
- **封面下半页需要第二道遮罩**：KPI 数字压在原图亮部会掉对比度。底部 4.6in 起 0→42% 的竖向遮罩
  既保住照片，也让白字站得住。
- **原始材料页按「印刷品」处理**：整列铺纯白（不是主题纸色，纸色会和图片自带的纯白之间出现一道边），
  左侧一根 accent 书脊，图按 contain 居中。图下不再写字——左栏已有文件名/尺寸/来源，重复即噪音。

### 数字排版（2026-11-19 夜）

- 英雄数字的**单位要小一号并坐同一条基线**：92pt 的「万」和 977.2 一样大是排版错误。
  拆成两个文本框（数字 92pt、单位 0.36×），单位 x = 数字宽度 × 1.05 + 8pt ——
  `text_width_pt` 是估算值，不计字距，不留 5% 余量单位就会压在最后一位数字上。
- **来源行跟着论点走**：把「销售额 · 区域 · 销售数据.xlsx」钉在页脚会在论点与来源之间
  留一个 1.7in 的洞；放在论点下方 0.55in 处，页面读起来是一个整体，底部留白就只是边距。

## 没有数字的时候（2026-11-19）

真实材料里有一半是 Word 和 Markdown，没有一张表。这类稿子最容易露怯：一页"暂无数据"、一页
空表格、一页"请联系我们补充"。所以纯文本走的是引用式排版，不假装有图表。

| 情形 | 版式 | 字号 | 规则 |
|---|---|---|---|
| 一句话 | quote | 40 → 24pt 自适应 | 深色页，150pt 引号，署名在左下 |
| 两句 | notes | 26pt | 一句一行，行间细线，出处用小字压在句式下 |
| 三到四句 | notes | 21pt | 同上，块整体垂直居中，不贴顶 |
| 标题 | — | 27pt | 「文档里的两句话」，数量由实际条数决定 |

三条硬规矩：

1. **不写没有的数字。** 挑句子时就排除含数字的句子；标题里也不出现数字。
2. **不改写原文。** quote 和 notes 都是原句，出处写在旁边，编辑可以据此回原文核对。
3. **宁可少一页。** 只有一句话就只出一页，不为了凑页数把一句话拆成三行。

## 从用户的模板里学排版（2026-11-19）

上传一份旧 deck，除了配色和字体，还能学到它的**字号尺度**：`ppt/slideMasters/slideMaster1.xml`
里 `<p:titleStyle><a:lvl1pPr><a:defRPr sz="4400">` 就是这份模板的标题字号（44pt）。

直接照搬会撑破我们的 12 栏网格，所以按 `0.68` 折算并夹到 24–33pt：44pt 的模板标题在我们这里
落到 30pt，比默认 27pt 更有分量，又不会把标题挤成三行。`Theme.head_pt` 为 0 时用默认值，
`_head()` 的 `_fit` 上下限都跟着它走。


## 对比页：把差距画成两栏（2026-11-19 增）

同比条形图让人自己找零线；对比页只留两个方向，把「往哪压」变成一眼的判断。

- **一栏一件事**：左「还在涨」、右「在退」，各自只放 2 个名字，第三个开始就是列表不是论点了。
- **一个名字一行**：`华东 +34.0%` / `西南 +19.0%` 用硬换行，绝不交给自动折行——一旦把 `+19.0%` 折成两行，数字的对比关系就断了。
- **字号就是音量**：40pt 粗衬线，两栏同字号，靠颜色（muted / accent）和位置分胜负，不靠大小。
- **中线只做分隔**：1pt 竖线，从标题下沿到正文底，不做卡片、不做底色。
- **结论带在底部**：15pt + 浅底 + 左侧 accent 竖条，一句话说清这页该拿它做什么决定。

## 数据页的三条硬规矩（2026-11-21 补）

1. **比较句必须有两个数**。标题写「客户数第一、销售额第五」时，表里就要同时出现这两个指标；只绑一个事实，等于让读者相信一半证据。`fact: "f13,f17"` 会生成第二列。
2. **单位跟着标签走，不单独飘**。「销售额 · 区域 · 元」是零件清单，「销售额 · 区域（元）」才是给人读的；标签本身已带括号时，把单位折进去：「客单价（均值 · 元）」。
3. **同一事实最多两页**。模型很容易把区域销售额同时用在 KPI、条形图和一张原始截图上——三页说了一句话。提示词与评审各拦一次。
4. **规划脚手架不进成稿**。副标题里出现 `f13`、`f17` 这类 id，说明那是给程序看的中间产物；渲染前直接丢掉，让模型重写一句人话。
