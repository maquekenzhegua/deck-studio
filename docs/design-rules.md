# 汇报 deck 的版式与叙事：竞品拆解、样本规律与可编码规则

> 目标不是"更好看"，是让"难看"变成可以被 `if` 判断的东西。
> 本文所有阈值都能落到 `deck/rules.py`，所有度量都能被 `python -m deck.audit` 复算。
>
> 证据标注：**【实测】** 本仓库 `out/demo.pptx` 上跑出来的数；**【规范】** 公开设计系统/咨询版式手册
> 的通行值；**【待校准】** 经验区间，需要用第 6 节的语料库分位数替换。

---

## 0. 五条判断（先给结论）

1. **用户说的"没有整体逻辑"，一半是叙事问题，一半是版式节奏问题，但两者都能被测。**
   叙事侧：相邻两页讲同一结论（p2/p3 都是"华东强、华北弱"），翻页没有信息增量。
   版式侧：6 页里 3 页是同一个 `chart` 版式，且 2–3 页连续同构 —— 读者无法从版式变化感知论证推进。
2. **"没有审美"在本项目里不是配色问题，是三个几何事故**：一页 4 种字号、19/24/34pt 不在阶梯上、
   图表内文字投影后只有 6.4–8.4pt。这三条都不是口味，是 bug。
3. **AI PPT 产品的共同短板恰好是我们的机会**：五款产品都在优化"单页好看"，没有一款优化
   "跨页论证"。它们没有事实层，所以做不到"这一页的结论必须由上一页的问题推出"。`deck` 有
   `compute.py` 的事实层，天然可以做"标题链 + 证据链"的硬校验。
4. **规则要分三层**，混在一起就变成审美争论：
   `geometry`（可 XML 测量，违规=bug，阻断）/ `density`（统计量，单页可宽容，系统性偏离=警告）/
   `semantics`（需要读者，自动只抓廉价特征）。
5. **留白不是越多越高级**。实测内容页墨迹 18%，读作"没内容"而不是"高级"。
   参考集的目标带是 35–70%，且同 deck 内字数变异系数 ≤0.35 —— 均匀比稀疏更重要。

## 2. 五款 AI PPT 的版式策略与叙事结构

拆的是**决策方式**，不是模板长相。模板长相会过时，决策方式决定了它在什么内容上必然崩。

| 产品 | 版式内核 | 谁决定布局 | 叙事结构 | 在什么内容上崩 |
|---|---|---|---|---|
| **Gamma** | 卡片（block）流，页面是卡片的排布结果 | 卡片自带 layout，按内容长度自适应 | 先出大纲/文档，再"卡片化" | 卡片间无共享基线 → 页内没有单一视觉重心；导出 pptx 是一堆散件 |
| **Beautiful.ai** | 约束求解（smart slide） | 设计师预置的规则引擎，用户只能选布局 | 弱，偏"单页装配" | 内容超出约束时缩字/溢出；跨页无节奏设计，全 deck 一个调子 |
| **讯飞智文** | 大纲 → 逐页套模板 | 模板匹配 + 公文版式 | **强**：长文本先结构化再成页 | 模板痕迹重；图表能力弱，数据页靠截图 |
| **islide** | 不是生成器，是排版工具集 | 人 | 无（不介入叙事） | 不解决"写什么"，只解决"对齐没有" |
| **WPS AI** | 模板库 + 单页美化 | 模板检索 | 弱：整篇换皮 | 换主题=换皮，论证链不随内容变化 |

### 逐条可迁移 / 不可迁移

**Gamma —— 可迁移：`1 card = 1 论点 + 1 证据`**
卡片模型的真正价值不是好看，是**强制一条内容单元只承载一个主张**。这条约束可以直接写进
`plan.py` 的 schema：一个 slide 只允许一个 `claim`，`evidence` 必须是 fact id 或图片 id。
不可迁移的是流式排布：它放弃共享基线，所以页面之间对不齐，而"对得齐"是汇报 deck 的信任来源。

**Beautiful.ai —— 可迁移：规则是硬约束，不是建议**
它的产品本质就是本文第 5 节的 `rules.py`：位置是解出来的，不是拖出来的。
我们的对应物是 `theme.py` + `verify.py` 的阻断级检查。不可迁移的是布局库思路 ——
布局数量永远不够，最终要么缩字要么溢出。规则应该是**参数化**的（列跨度、密度带），不是枚举的。

**讯飞智文 —— 可迁移：先大纲后版式**
叙事先行是对的，而且它的中文长文本结构化能力是五家里最实用的。
不可迁移的是"公文模板"审美：字号小、行距紧、满页文字，那是给打印阅读的，不是给投影演讲的。

**islide —— 可迁移：把"统一"做成可执行检查**
`一键统一字号/配色` 的本质是一次全量审计。我们的 `audit.py` 就是它的无人版：
不帮你改，只告诉你第几页第几个元素越界。
不可迁移：它假设有人在做设计决策，AI 生成场景下没有人。

**WPS AI —— 可迁移：模板即规则包**
把一套版式约束打包成可替换的 theme（未来"按去年那个 pptx 的格式来"就靠这个）。
不可迁移：检索式模板匹配不理解论证，换主题就丢逻辑。

> **共同空缺（我们的差异点）**：五款都只保证单页成立，没有一款能回答
> "这一页的标题，是不是上一页问题的答案"。这条只能靠事实层 + 标题链校验，见 R15。

## 3. 真实企业 deck 的六条版式规律

样本类型：咨询报告正文页（MBB 公开版）、上市公司业绩发布（IR deck）、大厂年度汇报。
规律按"能不能写成代码"排序。

### 3.1 栅格与边距 —— 唯一必须 100% 命中的一条

| 量 | 参考值 | 本仓库 | 结论 |
|---|---|---|---|
| 画布 | 16:9，13.333×7.5in | 同 | ✓ |
| 左右边距 | 画布宽的 5–7% | 0.85in = 6.4% | ✓ 在带内 |
| 上下边距 | 画布高的 7–9% | 上 8.3% / 下 7.3% | ✓ |
| 列数 | 12（或 6 的倍数） | 12 | ✓ |
| 列间距 | 画布宽的 1.4–1.8% | 0.22in = 1.65% | ✓ |
| 元素边缘吸附率 | ≥90% | 内容页 100% | ✓ |

**这条已经做对了，不要动。** 一个反直觉的事实：网格对了，页面仍然可以很难看 ——
因为网格只管"对不对齐"，不管"该放多少"。

### 3.2 留白：看的是"墨迹覆盖率"，不是"留白比例"

把每个元素的包围盒并集栅格化（图片按非白像素折算），得到墨迹占画布的比例。

| 页面类型 | 墨迹带 | 说明 |
|---|---|---|
| 封面 / 章节页 | 8–25% | 大标题 + 一条线，其余留空是刻意的 |
| 内容页（图表型） | 35–60% | 图表 55–65% 宽 + 右侧 2 条注释 |
| 内容页（文字型） | 45–70% | 一页一个论点 + 3 条支撑 |
| 结束页 | 25–45% | 结论复述，不新加信息 |

**关键不是下限，是方差**：同 deck 内内容页字数 CV ≤0.35。忽空忽满比整体偏空更伤 ——
它让读者感到"在凑页数"。实测 demo CV=0.107 看似合格，但那是因为**全体都偏低**（50–65 字），
所以 R09 的绝对带才是主检查项，R10 是辅助。

### 3.3 字号层级：阶梯要覆盖真实角色，每页只用 3 级

投影场景的约束是硬的：**正文不小于 17pt，图内文字不小于 11pt**（3m 观看距离，字高 ≥4mm）。

现行 5 级 `40/26/17/12/9` 覆盖不了两种真实角色：**大数字**（108pt）和**引导句**（20pt）。
于是 `render.py` 里出现了 6 处裸字号（18/19/20/24/34），全部越界。这不是疏忽，是阶梯不够用。

建议改为 8 级，但把约束强度放在"每页 ≤3 种"上：

```
96  display   关键数字（一页最多一个）
56  hero      次级数字 / 章节页数字
40  title     封面标题、结束页标题
26  section   内容页标题、编号行
20  lead      引导句、大数字旁注、图表注释
17  body      正文、要点
12  caption   轴标签、眉标、图注
 9  foot      来源、页码
```

比例 96/56/40/26/20/17 ≈ 1.71/1.4/1.54/1.3/1.18 —— 上疏下密，符合阅读的"先抓结论、后读细节"。

### 3.4 图表选型矩阵：先定关系，再定图形

| 你要表达的关系 | 唯一正确图形 | 禁用 | 备注 |
|---|---|---|---|
| 类别比较（≤8 类） | 横向条形，降序 | 纵向柱（中文标签会旋转） | 当前值 vs 基准值用双色同条 |
| 时间趋势（≥6 期） | 折线，端点标注 | 面积图（除非讲累计） | 中间点不标，只标首末与拐点 |
| 构成（≤4 类） | 堆叠条（100%） | 饼图/环图 | 5 类以上一律"其他" |
| 增减分解 | 瀑布 | 分组柱 | 汇报里最有说服力的一张图 |
| 转化/漏斗 | 漏斗，标每级转化率 | 金字塔 | 顶部 100% 时不讲 100%，讲最低环 |
| 相关 | 散点 + 趋势线 | 双轴折线 | 双轴是误导的高发区 |
| 排名变化 | 斜率图 / 哑铃图 | 多系列折线 | 两期对比最清楚 |

一页一图，图占内容宽 55–70%；**不要图例**（直接标在系列上）；不要网格线（除零线/基准线）；
数据标签就是正文，字号 ≥11pt。

### 3.5 信息密度：咨询页 120–220 字，AI 生成页 40–70 字

| 类型 | 每页汉字（含标题/注释/来源） | 结构 |
|---|---|---|
| 咨询正文页 | 150–220 | 行动标题 + 图 + 2–3 条 so-what + 来源 |
| 上市公司业绩页 | 180–260 | 标题含数字 + 表格/桥图 + 口径脚注 |
| 大厂年度汇报 | 100–160 | 标题 + 3 条 + 一张图，口语补充 |
| **AI 生成 deck（现状）** | **40–70** | 标题 + 2 条短句，无证据层 |

差距不在"字多"，在**证据层**：咨询页的每一个断言后面跟一个数或一个对比基准。
`deck` 已经有 fact 层，缺的是"把 fact 放进页面"的版式（现在的 chart 页只放 2 条 bullet）。

### 3.6 视觉重心与对齐线

- 面积加权质心落在画布中心 ±10%（x 38–62%，y 40–58%）。贴边 = 页面"歪"。
- 每页至少一条贯穿横线：标题基线、页脚线、或图表底线。三选一，且全 deck 一致。
- 页脚是唯一每页都出现的元素，它一旦浮动，整本 deck 的"装订感"就没了。

## 4. 叙事结构：三种 deck 的骨架

版式规律解决"这一页好不好看"，骨架解决"为什么要有这一页"。

### 4.1 经营汇报（本项目的主场景，8 页）

| 页 | 角色 | 标题句式 | 版式 | 密度 |
|---|---|---|---|---|
| 1 | 封面 | 结论式主标题 + 口径副标题 | title | 8–15% |
| 2 | 结论 | 「三条结论，每条一个数」 | 3 行编号列表 | 45% |
| 3 | 全景 | 「营收 X，同比 Y，超/欠预算 Z」 | 4–6 个 KPI 卡 | 40% |
| 4 | 增长来源 | 「增长 N% 来自 A，B 是唯一负增长」 | 瀑布/堆叠条 + 2 条注释 | 50% |
| 5 | 问题诊断 | 「C 环节流失最重，低于行业 P50」 | 对比条形 + 基准线 | 50% |
| 6 | 归因 | 「C 的根因是 D，不是 E」 | 2×2 或因果链 | 40% |
| 7 | 行动 | 「三件事，各自的 owner 与验收」 | 3 行表格（不是 bullet） | 55% |
| 8 | 下一步 | 「未来 30 天的三个里程碑」 | 编号列表 | 35% |

**硬规则**：第 2 页的每条结论，必须在第 3–6 页里各有一页证据；第 7 页的每个动作，
必须对应第 5–6 页的一个问题。对不上就是"没有整体逻辑"。

### 4.2 咨询 deck：SCQA + 金字塔

S（情境）→ C（冲突）→ Q（问题）→ A（答案，即全篇结论）→ 逐层 MECE 支撑。
每页 = 一个行动标题 + 一个证据 + 一句 so-what。上一页的结论是下一页的**问题**，
不是下一页的**话题**。检验方法：把标题连起来读，应该是一段连贯的论证，不是一串名词。

### 4.3 上市公司业绩发布：摘要 → 分部 → 现金/资产 → 指引

读者是分析师，不是观众，所以密度最高（180–260 字），图表以 YoY 桥（bridge）为主。
可迁移的一条：**所有数字都带口径脚注**。这与 `verify.py` 的来源校验是同一件事的两面。

### 4.4 大厂年度汇报：目标回顾 → 关键战役 → 数据 → 复盘 → 明年三件事

每页一个战役，固定"左图右文"节奏，3–5 个战役正好构成 3–5 页同构 —— 这是**允许**的重复，
因为重复本身就是"并列关系"的信号。区别在于：并列页必须在标题里体现同一层级
（「战役一：…」「战役二：…」），而不是让读者猜。

> 这条解释了 R12 为什么要设"连续 ≤2 页"而不是"禁止重复"：
> **同构 = 并列**是合法修辞，**同构 = 词穷**才是问题。判别方法是标题是否成对出现层级词。

## 5. 规则清单（已落到 `deck/rules.py`）

| ID | 规则 | 门槛 | 层 | 门禁 |
|---|---|---|---|---|
| R01 | 画布与边距镜像 | 左右 6.0–7.0% 宽；上下 7.0–9.0% 高；左右相等（±0.02in） | geometry | block |
| R02 | 栅格吸附 | ≥90% 的对齐边落在 12 列线（±0.02in） | geometry | block |
| R03 | 字号阶梯 | ∈ `theme` 全部 `FS_*` ±0.5pt；单页 ≤4 种（标题/正文/注释/页脚） | geometry | block |
| R04 | 标题区比例 | 标题带到正文占画布 15–22% | geometry | warn |
| R05 | 行长 | 实际折行的正文 ≤34 字/行（单行文案不受限） | geometry | warn |
| R06 | 图表内字号 | 折算后 ≥11pt；**由源码扫描判定**（.pptx 里只有像素） | geometry | block |
| R07 | 页脚基线 | 底部小号元素同一 y（±0.02in）；左右贴内容边界 | geometry | warn |
| R08 | 墨迹覆盖 | 内容页 35–70%；封面/章节 8–25% | density | warn |
| R09 | 单页字数 | 内容页 80–240；图表页 60–200 | density | warn |
| R10 | 密度方差 | 同 deck 内容页字数 CV ≤0.35 | density | warn |
| R11 | 强调点配额 | 单页彩色 ≤2 处；全 deck 强调色 ≤2 种 | density | warn |
| R12 | 版式节奏 | 同 layout 连续 ≤2；占比 ≤40%；≥4 种 | density | warn |
| R13 | 视觉重心 | 质心 x∈[38,62]%，y∈[40,58]% | density | warn |
| R14 | 标题是论点 | 含判断/数字；不以「分析/情况/汇报/总结」结尾 | semantics | warn |
| R15 | 标题接龙 | 相邻标题 Jaccard ≤0.34；连读成论证 | semantics | warn |
| R16 | 一页一论点 | ≤3 条要点，且都支撑标题 | semantics | human |
| R17 | 来源与页码 | 数据页有来源；页码连续 | semantics | block |

**为什么这样分层**：把"字号越界"和"标题像目录"放在同一层，讨论就会退化成审美争吵。
几何层的违规是**事实错误**（文件里就是 19pt），语义层的违规是**判断**（需要读者）。
门禁强度必须不同。

### 规则之间的冲突与豁免

- 封面、章节页豁免 R02/R04/R08/R09（它们刻意用 insets 与大面积留白）。
- 并列型页面（战役一/二/三）豁免 R12 的连续限制，但标题必须带层级词。
- 图片不计入 R02：contain-fit 的图片边缘由长宽比决定，不是对齐决策。
- 表格页天然不触发 R05：单元格不按行折行成段落，列宽由内容决定；但仍受 R09 密度约束。

## 6. 可执行采集方法

规则的可信度来自样本分位数，不来自"我觉得"。下面是能跑的做法。

### 6.1 样本池（30 份 × 8–12 页 ≈ 300 页）

| 类 | 数量 | 来源类型 | 取页规则 |
|---|---|---|---|
| A 竞品输出 | 5 | 同一份 2000 字中文材料喂 Gamma / Beautiful.ai / 讯飞智文 / islide / WPS AI，导出 pptx | 全部 |
| B 咨询正文 | 10 | MBB 公开报告 PDF | 跳过封面/目录，取连续 10 页正文 |
| C 企业披露 | 10 | 上市公司 IR deck、大厂年度汇报 PDF | 取"摘要 + 分部 + 指引"各 2–3 页 |
| D 反例 | 5 | 社交平台"AI 生成 PPT"晒图 | 全部（做负样本对照） |

### 6.2 采集脚本

```bash
# PDF：页图（看版式）+ 文本层（算字数）
mkdir -p samples/corpus/B/mck__q3
pdftoppm -r 200 -png -f 12 -l 21 ref.pdf samples/corpus/B/mck__q3/page
pdftotext -layout ref.pdf samples/corpus/B/mck__q3/text.txt

# PPTX：直接出指标（本文的 audit）
python -m deck.audit samples/corpus/A/gamma__demo.pptx --json \
  > samples/corpus/A/gamma__demo/meta.json

# 页图裁切：去掉白边后再算墨迹，否则 PDF 自带的页边距会污染
python - <<'PY'
from PIL import Image, ImageChops
im = Image.open("page-12.png").convert("RGB")
bg = Image.new("RGB", im.size, (255, 255, 255))
box = ImageChops.difference(im, bg).getbbox()   # 内容真实包围盒
print(box, im.size)
PY
```

### 6.3 标注协议（每页 14 个字段）

```json
{
  "id": "B/mck__q3/page-12",
  "role": "content|cover|section|closing|table",
  "title_text": "……",
  "title_type": "claim|topic|question|number",
  "layout": "chart_left|chart_full|text_3col|matrix|timeline|table|kpi_row|image_full",
  "chars": 168,
  "ink": 0.52,
  "font_sizes": [26, 17, 12, 9],
  "chart_type": "waterfall",
  "has_source": true,
  "has_page_number": true,
  "columns_used": 12,
  "so_what": "一句话：这页想让读者记住什么",
  "note": "肉眼可见的问题"
}
```

- 自动字段（可从 pptx/pdf 直接算）：chars、ink、font_sizes、has_source、has_page_number、columns_used。
- 人工字段（必须人读）：title_type、layout、chart_type、so_what、role。
- **双人重叠 20%**，`title_type` 与 `layout` 用 Krippendorff α 检验，α <0.7 就重写标注手册。
  标注手册不写清楚，"审美"就会从后门回来。

### 6.4 评价口径：三个代理指标，不打"美观分"

| 指标 | 算法 | 目标 |
|---|---|---|
| 密度稳定性 | 同 deck 内容页字数的 CV | ≤0.35 |
| 栅格一致性 | 对齐边命中列线比例 | ≥0.90 |
| 标题链可读性 | 3 人独立读标题串，判断"是否构成论证"（0/1） | ≥2/3 通过 |

"美观"不可测，但"密度稳定 + 对齐一致 + 标题连读成句"是可测的，且与观感高度相关。
真要主观分，用**成对比较**（A/B 二选一）而不是 1–10 打分 —— 后者方差大到没有信息量。

### 6.5 阈值校准（本文最诚实的一段）

R08/R09/R10 的带目前是经验值【待校准】。校准方法：

```python
# 取 B+C 两类 20 份参考 deck 的内容页，算 P25 / P75
import json, statistics
vals = [m["chars"] for f in refs for m in load(f)["slides"] if m["role"] == "content"]
print(statistics.quantiles(vals, n=4))   # → 用 P25–P75 替换 80–240
```

校准前，这些阈值只能当"警告"，不能当"阻断"。R01/R02/R03/R06 是几何事实，可以先阻断。
