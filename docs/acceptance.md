# 验收：一次解压、一份资料、一套成稿

这份记录不是「我觉得能用」，而是一条可重复的命令和它的输出。

```bash
python tools/accept.py            # 用 dist-v23 里的打包版
DECK_EXE=... python tools/accept.py   # 换一个构建
```

脚本会：新建一个空的工作区 → 用 HTTP 上传 `samples/data` 全部 7 个文件 → 抽取事实 → 生成 15 页 → 导出 PDF → 清理桌面上的导出物。每一步都断言，任一失败即退出码 1。

## 这份输出说明了什么

- **不装 Python 也能跑**：上面所有请求都发给 `dist-v23/Deck Studio/Deck Studio.exe`，它自带解释器与依赖。
- **不装 Office 也能预览**：预览走 LibreOffice 无头转换；转换失败时会退回 PowerPoint COM，两者都没有时仍能出 `.pptx`，只是没有缩略图。
- **不填模型也能出稿**：规划走离线规则（`compose`），模型只提升表达，不参与「数字从哪来」。
- **数字可核对**：`verify` 在渲染前把每个数字和事实表对齐，0 个问题才写出文件。
- **多模态不是口号**：Excel 单元格与原生图表、PDF 正文与页面表格、Word 内嵌图、PPT 图表数值与模板配色，都进同一份事实池。

## 还需要人来判断的部分

机器能测的是「有没有错、够不够满、数字对不对」。测不了的是这场汇报的现场：听众是谁、上一页讲了什么、老板会在哪一句打断。这些仍然要人改——所以每一页都能在界面里改标题、换版式、换成自己公司的模板配色。
